# 云台姿态工作台与控制源码

更新：2026-11-20。文档基线：已合并 PR #5（main a6ac819），本轮仅同步文档及文档入口标题，不改算法、参数或控制逻辑。

## 现在能做什么
云台控制程序执行运动 → 厂家 WitMotion 上位机记录 WT61PC → 导出同次 CSV/BIN 与控制日志 → 工作台导入检查、对齐、算法对比、三维回放和导出。
工作台不直接连接传感器、BGC 或 CAN，不会启动云台。运行时资源本地打包；安装源码依赖需要相应环境/网络。项目定位是实验演示与算法验证工具，不是已经完成独立精度认证的测量产品。

## 六轴主页面
- 默认进入六轴分析。固定 WitMotion 中文 CSV 可用“导入记录（自动识别）”，也可同选配套 BIN；其他格式使用手动映射。片上时间异常不会静默换成电脑时间。单位、安装方向和来源仍需人工核实。
- 一次成功导入的六轴记录供分析、三维回放和位置角页共用；软件干扰分支同样共享。旧位置角页面保留独立导入/演示能力，不会凭空生成原始 IMU。
- 主算法为标准一次 ESKF（A0）与固定先验切空间双侧白化 Huber IRLS ESKF（A4）。三维回放可选标准/鲁棒输出；原 CSV 有有效且对应的姿态列时可增加传感器姿态对照，非真值。相对 Yaw 不等于绝对航向。
- 原有位置角每轴 [角度,角速率] KF/Huber KF 及平滑回退仍用于旧演示，不是六轴 ESKF。旧 imuEkfInterface.ts 占位接口不代表 sixAxisEskf.ts 不可用。

## 软件干扰与九宫格
“软件干扰演示”在原日志副本约 40% 时刻向 ax 加 +3 m/s² 短时脉冲（最长 0.2s，实际窗口/命中数显示在界面）。不发设备指令，不覆盖原日志，重复点击不叠加，新导入清除分支。它不是实际外力干扰或真实精度证据。

九宫格默认折叠：左列估计值；中列各算法相对自身未注入结果的环绕角度偏差；右列全局平均 Wy/Wx，各行重复同一组全局值，不是每轴独立权重。权重直接来自算法已保存的迭代诊断量，未做显示平滑。仅传播帧的默认权重 1 不代表接受观测；应结合状态解释。输入/九宫格支持同步游标。导出包含软件注入说明、偏差、均值权重及传播状态。

## 双日志叠加（PR #5）
支持六轴数据与可选上位机控制指令 CSV；也可点击“叠加指令CSV”追加。指令至少含 elapsed_s、yaw_position_deg、roll_position_deg、pitch_position_deg，完整三轴 rpm 列可选。

黄色虚线为指令/估算轨迹，绝非编码器实测位置。时间偏移定义为 sensor_time = command_time + offset；仅在重叠范围内线性插值。可按首个重叠帧对齐起点姿态，这是显示/比较对齐，不是硬件同步或真实标定。界面当前显示 A4 相对对齐指令的 RMSE/最大偏差，不是独立真值精度。不同页面不保证全部绘制指令叠加层；该层目前用于六轴 ESKF 对比图。插值也不是恢复更高频率的真实控制采样。

## 数据检查与导出
- 保留电脑时间追溯，不按重复电脑接收时间删行；检查非有限值、主时间重复/逆序、单位换算和缺列。
- BIN 检查包边界、校验、包数和尾部不完整组，不能当作通道严格硬件同步证明。仅 CSV 明确标为未进行二进制验证。内部缺包与 CSV 行对应关系仍应人工复核。
- 支持规范化七列 CSV、质量报告、六轴算法对比和九宫格偏差/权重导出；旧角度 KF 有三轴诊断导出，平滑回退不能生成 KF 诊断。

```
npm ci

npm run build
npm run preview -- --host 127.0.0.1
```
